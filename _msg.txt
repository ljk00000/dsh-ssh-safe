fix: apply validated nothing, so the schema checks never ran

1. apply() built its config as { ...Config(), ...(config || {}) }: it took the
   defaults and overwrote them with the user's values. The enum schemas only
   ran when the DSH host called Config() itself, which is not the path the plugin
   loads through -- so execGuard: "yes" reached the running plugin, and since
   "yes" is not "confirm", the confirmation guard was silently OFF while the
   config displayed something that looked enabled. The same hole let
   maxConnections: "abc" through, where Number("abc") is NaN and the ceiling
   was quietly removed. apply() now validates through the schema and fails the
   load with a message naming the setting and its allowed values.

2. Tool arguments were described in `parameters` but never checked. A shared set
   of validators rejects wrong types and non-positive numbers before any network
   work, instead of surfacing them as ECONNREFUSED or hiding them behind the
   reconnect cooldown.

3. ssh_write wrote the four characters "null" when content was null.

4. sftp.js: 15 direct tests. It was the only module without any, so its error
   and deadline branches had never executed. One of its four reject paths also
   skipped redaction while the other three applied it.

5. Every source file carries an SPDX header; the README states the DSH, Node and
   sshd requirements and the known limits.

6. Version 0.2.0 with a changelog entry and a git tag, instead of 14 commits on
   0.1.0.

Tests: 165 passing, 4 skipped. Typecheck clean.
