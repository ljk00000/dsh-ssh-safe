feat: an on-demand local page for machines and credentials

The settings form covers machine definitions, but entering a password there would
write it to the DSH config file in plain text, and the helper script only covers
passwords had no GUI at all. This adds a page that does the whole job and then
disappears.

`node scripts/gui.mjs` opens 127.0.0.1 on a random port with a per-start token in
the URL. It lists every alias from all three sources, edits host / port / user /
key path, stores a password DPAPI encrypted the moment it is saved, and runs a
real connection test that reports 配置 / TCP / 主机密钥 / 认证 / 命令通道 in order.

A separate process, not a server inside the plugin: the plugin keeps no listening
socket, which is what "no cloud, no ports" promised. The page exists only while
the command runs and exits on close or after ten idle minutes. One local HTML
file, no CDN, no telemetry.

Two deliberate limits:
  * the test reports the host-key fingerprint but does not record it -- a test
    must not move the trust state, the same rule ssh_doctor follows;
  * when a machine's host or user comes from the DSH settings form, editing it
    here returns a warning instead of silently losing to that precedence.

9 tests drive the real server: token refusal, that no endpoint returns the
password, that the file holds ciphertext only, that an unreachable host is
reported rather than thrown, that a bad port is rejected before anything is
written, and that shutdown exits cleanly.
