fix: the deny list was bypassed, the audit file was world-readable

1. rm -rf /* and rm -rf --no-preserve-root / got through. The root pattern
   required a whitespace or end-of-string after the slash, and canonicalizeRm
   deleted every short-flag token, so --no-preserve-root vanished and left
   'rm -rf -', which no longer matched. The pattern now accepts a glob, and
   the canonicaliser keeps unknown long options as words and emits one
   canonical flag cluster.

2. 'curl x | sudo bash' got through: checkPipeline looked at the first word on
   the right of the pipe, which was sudo. Privilege and environment prefixes
   are stripped first now, and a privileged writer (sudo tee, dd of=/dev) is
   caught too. Ordinary pipes are unaffected.

3. The guard was a no-op. The 'return true' added to guard() when the confirm
   check was introduced landed BEFORE the pattern check, making the whole body
   unreachable -- every command passed unexamined since. Both guards are now
   covered by tests.

4. execGuard confirm gated ssh_exec only. ssh_write could drop a script or a
   line into ~/.bashrc without confirmation, which for an agent is often the more
   dangerous half of the work. Writes are gated too.

5. The audit file was created with the default mode, so every account on the
   machine could read hosts, commands and paths. It is now 0600 where POSIX
   modes apply.

6. The audit log rotated by overwriting .1 and recent() read only the live
   file, so records older than the last rotation were unreachable -- exactly the
   window that matters after an incident. Four generations are kept and read
   back in order.

7. redact handled KEY=value and PEM only. An Authorization header or a
   password inside a URL went through untouched, and ssh_read returns exactly
   that text. Bearer/Basic credentials and scheme://user:pass@host are now
   masked.

8. ssh_read still used inline argument parsing: an earlier edit to the
   validators did not match this tool's block and failed silently, while my
   check searched the whole file rather than this tool. It now uses the shared
   validators like every other tool, and the check is per-tool.

9. package.json files omitted SECURITY.md and CHANGELOG.md, so publishing
   would have dropped the security documentation.

Tests: 189 passing, 4 skipped. Typecheck clean.
